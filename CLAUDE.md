# Моя неделя (timetable)

PWA без сборки: всё приложение — один файл `index.html` (CSS + JS внутри), плюс `sw.js` (офлайн-кэш) и `manifest.webmanifest`. Зависимостей нет.

## Правила
- **После любых изменений файлов приложения увеличивай `VERSION` в `sw.js`**, иначе установленное приложение не обновится.
- В коде нет личных данных: расписание, планы, задачи и т. п. приходят из файла копии / с сервера синхронизации и живут в `localStorage` (`moya-nedelya-v1`).
- Интерфейс и тексты — на русском. Стиль кода — плотный, однострочные функции, шаблонные строки с `esc()` для пользовательского текста.

## Данные (`DB`)
- `weeks.odd/even[7][]`, `dated[iso]` — расписание (шаблон недели и изменённые дни); событие может ссылаться на план через `ref`.
- `plans[id] = {title, type, body, exercises?}` — планы. Расписание и планы — одно целое: меняешь их → `saveSched()` (ставит `schedAt`, сохраняет, запускает синхронизацию). При импорте/синхронизации `mergeIn` берёт расписание+планы целиком у той стороны, где `schedAt` новее.
- `tasks`, `workouts`, `bodyweight`, `lists`, `listItems` — объединяются по `id` с учётом `updated` и меток удаления `deletedTasks`. Меняешь запись → обнови её `updated`.
- `normalize()` применяется к локальным данным, к импортируемой копии и к ответу сервера — миграции формата делать там.

## «Зал»
- Программа тренировки — план с `type:"gym"`; упражнения в `plan.exercises = [{id,name,sets,repsMin,repsMax,restSec,stepKg,bodyweight,note}]`. Текст `body` — только описание (разминка, техника, правила).
- Миграция: если у «зального» плана нет `exercises`, `normalize()` один раз собирает их из текста (`exercisesFromText`, строки вида `1. **Присед** — 4×5–8`; id детерминированные `<planId>-<n>`). То же при сохранении плана, который впервые стал «Залом». Дальше текст на упражнения не влияет.
- Редактор программы: `renderProgEditor` (экран внутри вкладки, `UI.gymEdit = planId`), `openExEditor`, `openNewProgram`. Каждая правка сразу пишется в план и сохраняется через `saveSched()`.
- История и графики привязаны к названию упражнения (сравнение через `nkey`). При переименовании, если есть история, спрашиваем; `renameHistory` переименовывает упражнения в `workouts` (с новым `updated`) и в идущей тренировке.
- Идущая тренировка `ACTIVE` (`localStorage` `moya-nedelya-v1-active`, не синхронизируется) — снимок программы на момент старта; правки программы применяются только к следующей тренировке.

## Проверка
Локально: `python3 -m http.server` в папке репо и открыть `index.html` (service worker регистрируется только по https). Для e2e удобен Playwright (Python) с `channel="chrome"`; данные подкладываются в `localStorage` через `add_init_script`, сервер синхронизации — через `context.route`.
